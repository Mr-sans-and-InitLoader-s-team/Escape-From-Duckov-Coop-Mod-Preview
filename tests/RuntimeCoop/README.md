These tests run two, three or four copies of the installed native game with separate save directories. They are local test tools and are excluded from the production mod package.

`Prepare.ps1` creates the private copies once. Read-only game data uses hard links/junctions; managed assemblies are copied before patching the test bootstrap and persistent-data path. Do not patch the installed game's managed assemblies. `Start.ps1` loads the staged mod and test runner into the copies, starts D3D11 batch mode and records their process IDs.

The runner blocks `InputManager.Update`, `CharacterInputControl.Update`, input-event registration and `Mouse.WarpCursorPosition`, and uses manual InputSystem event updates. Cursor state alone is insufficient: the game also warps the cursor directly. Do not switch these tests to interactive windowed instances on the user's desktop. Do not use `-nographics`: native input, shader and animation initialization differ in that mode.

`driver.py` sends commands through files and reads native owner/replica states. `udp_proxy.py` delays and drops raw UDP datagrams before the transport's retransmission logic. Each client needs its own proxy port (19051, 19052 or 19053). Profile delays are one-way values; this affects direct transport only. Four-player Steam P2P needs four independently authenticated accounts; instances signed into the same Steam ID do not prove Steam P2P.

The suites exercise actual native combat, Buff managers, physics explosions, inventory factories, saves, scene votes, teleporter/countdown callbacks and settlement continuations. Accelerated expiry changes the native start timestamp, then waits for the native Buff manager to expire the effect. Synthetic corpse fixtures are separate from real death/revisit acceptance. Record native effects that reject an addition or expire immediately as such, rather than counting them as successful persistent effects.

Keep owner state fresh before comparing a replica. Two equal stale snapshots are not evidence of convergence. Preserve failed and preliminary results; reruns need an explicit revision or a separate output file.

`corpse_journey.py` covers real host/client deaths, partial looting, spectator target changes, native extraction, delayed settlement and subsequent raids. `four_player_maps.py` records conditional exits separately from completed evacuations. `additive_stress.py` alternates actual teleporter initiators across network profiles; AI replicas also carry the player replica tag and must be excluded from player counts. `world_persistence.py` checks drops, partially looted containers, doors and broken objects after a round trip. Runtime transport diagnostics expose native reliable queues when a weak-network transition stalls. Do not mark a recovery under a different network profile as a pass for the original profile.

Front-end mouse/aim behavior, rendered spectator smoothness, foreground frame rate, locked/quest-gated routes, and authenticated two-machine Steam P2P remain separate acceptance checks. Stop only the recorded test executable paths, and compare the original save hashes after the run. Never deploy `CoopRuntimeTests.dll` or the patched private engine assemblies to the normal mod directory.

`drop_rejoin.py` checks drops created while a peer is disconnected, inactive-scene ownership, unique physical agents, return visibility and pickup propagation. `weak_portal_recheck.py` retains live drops during the 800 ms / 10% loss route and records reliable queues. Native breakables with `save=false` are expected to reset after a scene reload. Survival/Island settlement has an extra native confirmation before the ordinary Continue button; the test confirms that visible native view through its own field, without moving the desktop mouse. Each player receives test invincibility as soon as its map initializes, so a faster-loading host cannot die while waiting for the other copies.

`final_verification.py` repeats rapid native weapon switching, then checks AI range reentry, actual native-trigger friendly-fire shots, and drop recovery across reconnect/additive scenes. Weapon comparisons require fresh owner state and three stable seconds. AI range coverage requires more than 350m distance and an observed inactive replica before returning; a nearby 160m move does not cover the default snapshot filter. Ground placement also checks that the native character remains at the supported height before using the site.

`hit_performance.py` profiles the native damage path separately from weapon firing, with source-specific host damage records, native hit-marker counters and frame timings. `hit_feedback_acceptance.py` checks native UI creation/destruction, reliable queue drain under 800 ms RTT / 10% loss, per-frame native automatic-weapon triggers, kill feedback and evacuation. Keep one observation window across bursts and reloads because client feedback precedes host settlement. The optional `--skip-weak` flag runs the independent native-gun/lifecycle checks after a separately recorded weak-network run. Mono allocation counters can be unavailable; report those as null rather than zero allocations.

`loot_door_baseline.py` and `loot_door_acceptance.py` cover shared-position door variants, native construction removal, per-player inspection and client corpse recovery. Confirm a new player corpse by its tomb prefab and position; unrelated AI deaths can also allocate loot IDs. Native search uses `CharacterMainControl.Interact`, and native pick-all remains separate from the partial-stack mutation probe. Wake the native distance-culling region before checking its ground colliders. Construction reset fixtures change only private test instances. `DeadLootSpawnRpc` ownership is distinct from its current-death notification, so restoring an old corpse must leave all living replicas present.
